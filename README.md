# Інформаційна система реєстрації інцидентів громадського транспорту

**Курсова робота з компонентного програмування — варіант №20.**

Програмна система призначена для обліку маршрутів і транспортних засобів, реєстрації інцидентів громадського транспорту та керування завданнями реагування. Система складається із серверної частини на Java та настільного клієнта JavaFX. Дані зберігаються в MySQL, а взаємодія між компонентами здійснюється через HTTP API з JSON.

## Функціональні можливості

- Перегляд, додавання, редагування та видалення маршрутів.
- Перегляд, додавання, редагування та видалення транспортних засобів із прив'язкою до маршруту.
- Реєстрація, перегляд і видалення інцидентів.
- Послідовна зміна статусу інциденту: **ПОВІДОМЛЕНО → ПІДТВЕРДЖЕНО → РЕАГУВАННЯ → ЗАКРИТО**.
- Обчислення інтегрального показника інциденту на сервері.
- Створення, редагування та видалення завдань реагування.
- Фоновий імпорт транспортних засобів та інцидентів із CSV-файлів із відображенням прогресу та помилок.
- Графічний інтерфейс JavaFX із CSS-оформленням.

## Архітектура

```text
JavaFX Client
    |
    | HTTP / JSON
    v
Servlet (Tomcat 9)
    |
    v
Service (бізнес-логіка)
    |
    v
DAO (доступ до даних)
    |
    v

```

Сервер відповідає за перевірку та обробку даних, правила зміни статусів і розрахунок показника. Клієнт відображає дані та надсилає запити до API.

## Вимоги для запуску

1. **JDK 21** і налаштована змінна `JAVA_HOME`.
2. **Apache Maven**.
3. **MySQL** (можна запустити через XAMPP).
4. **Apache Tomcat 9**.
5. Доступний порт **8080** для Tomcat.

## Налаштування бази даних

1. Запустіть MySQL.
2. Створіть базу даних **`transport_incidents_v20`**.
3. Імпортуйте SQL-скрипт проєкту (`database.sql`) через phpMyAdmin або MySQL CLI.
4. Перевірте JDBC-налаштування сервера: адресу, порт, назву БД, ім'я користувача та пароль.
5. Не публікуйте реальні паролі та локальні конфігураційні файли з секретами у GitHub.

Приклад перевірки в MySQL:

```sql
USE transport_incidents_v20;
SHOW TABLES;
```

## Збірка та запуск сервера

У терміналі відкрийте папку `server`:

```powershell
cd server
mvn clean test
mvn clean package
```

Після успішної збірки Maven створить WAR-архів у папці `server/target/`. Розгорніть **`server.war`** у Tomcat 9 (контекст `/server`) та запустіть Tomcat.

Якщо Windows не дозволяє видалити `server/target` під час `mvn clean`, спочатку зупиніть Tomcat і процеси, що використовують результати збірки.

### Перевірка API

Після запуску сервера доступні GET-ендпоїнти:

| Дані | Адреса |
| --- | --- |
| Маршрути | `http://localhost:8080/server/api/routes` |
| Транспортні засоби | `http://localhost:8080/server/api/vehicles` |
| Інциденти | `http://localhost:8080/server/api/incidents` |
| Завдання реагування | `http://localhost:8080/server/api/tasks` |

Залежно від наявних записів API повертає JSON-масив об'єктів або порожній масив `[]`. Операції створення, оновлення, видалення та зміни статусів клієнт виконує через POST-запити до відповідних ендпоїнтів.

## Запуск JavaFX-клієнта

У **другому терміналі**, коли MySQL і Tomcat уже запущені:

```powershell
cd client
mvn clean compile
mvn javafx:run
```

Клієнт використовує адресу API:

```text
http://localhost:8080/server/api
```

У програмі передбачено чотири вкладки: **Маршрути**, **Транспорт**, **Інциденти**, **Завдання реагування**.

## CSV-імпорт

Імпорт запускається кнопкою **«Імпорт CSV»** у вкладках «Транспорт» або «Інциденти». Обробка виконується у фоновому завданні JavaFX, щоб інтерфейс залишався доступним. Після завершення відображаються кількість оброблених, успішно імпортованих і пропущених рядків та повідомлення про помилки.

**Формат CSV для транспорту:**

```csv
registration_number,vehicle_type,model,route_id
BI2345AA,Автобус,Богдан А092,1
BI4567AC,Тролейбус,Богдан Т701,2
```

**Формат CSV для інцидентів:**

```csv
vehicleId,routeId,description
1,1,Затримка руху на маршруті
2,1,Технічна несправність
```

Важливо:

- Кодування файлів — **UTF-8**.
- Заголовки повинні точно відповідати наведеним назвам і порядку колонок.
- Ідентифікатори маршрутів і транспортних засобів мають існувати в базі даних.
- CSV-імпортер використовує просте розділення за комою; поля з комами всередині тексту та повний формат CSV із лапками не підтримуються.
- Повторний імпорт може призвести до конфліктів унікальності або дублювання записів залежно від обмежень бази даних.

## Інтегральний показник інциденту

Інтегральний показник визначається формулою:

\[
I = 0.40F_1 + 0.35F_2 + 0.25F_3
\]

де `F1`, `F2`, `F3` — фактори оцінювання інциденту (0–100). Обчислення та збереження значення здійснюються серверною частиною.
